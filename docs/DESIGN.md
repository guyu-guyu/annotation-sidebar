# 设计说明

## 问题分类与骨架

这是一个“编辑器扩展 + 按文档关联的旁路数据”问题。首版按以下骨架实现：

```text
批注数据模型 → Vault 仓库层 → 编辑器捕获/定位 → 原生侧栏 → 生命周期同步
```

每层只依赖前一层：`core.ts` 不依赖 Obsidian，可独立测试；`repository.ts` 只负责文件一致性；视图和编辑器扩展通过仓库访问数据。

## 存储选择

| 方案 | 优点 | 问题 | 结论 |
| --- | --- | --- | --- |
| 写入 Markdown 正文 | 可跟随正文同步 | 污染笔记，格式和渲染耦合 | 不采用 |
| 插件目录中的集中数据库 | 文件数量少 | 难以按笔记同步、迁移和版本管理 | 不采用 |
| 每篇笔记一个 JSON 伴随文件 | 隔离正文、可移植、可审查 | 会增加文件数量 | 采用 |

默认路径映射是 `Folder/Note.md → Folder/Note.annotations.json`。最后一条批注被删除时，空伴随文件会被删除。

## 锚点模型

只保存行号无法抵抗正文前方的编辑。因此每个锚点同时保存：

- 起止偏移与行列，提供快速定位和最终回退。
- 被选中的原文 `quote`，用于在正文中重新搜索。
- 锚点前后的各 48 个字符，处理相同原文出现多次的情况。

定位顺序如下：

1. 原始偏移处的原文仍相同，直接命中。
2. 搜索所有相同原文，按前后文匹配长度和距原位置的距离评分。
3. 位置批注搜索“前文 + 后文”的边界，再分别尝试前文末尾和后文开头。
4. 均失败时回退到合法范围内的原始偏移，并在跳转时提示。

编辑器加载批注时会把持久化锚点解析为当前文档偏移。之后每次 CodeMirror 编辑事务都会同步映射这些实时偏移，并在同一事务中重建高亮、位置标记和正文批注块；普通正文输入不会重新读取伴随文件。伴随文件、当前笔记或展示设置变化时才异步重载批注，重载同一笔记时会按批注 ID 保留已有实时位置。

## 写入一致性

- 首次批注使用 `Vault.create`。
- 后续更新使用 `Vault.process`，在同一个原子回调中解析、修改并序列化。
- 格式损坏时拒绝覆盖原文件，侧栏展示文件路径和错误。
- 插件标记自己的写事件，避免 Vault 的 `modify` 回调反复重绘正在输入的侧栏。
- 删除笔记时通过 `FileManager.trashFile` 处理伴随文件，遵循用户的 Obsidian 废纸篓配置。

## UI 边界

侧栏继承 Obsidian `ItemView`，图标使用内置 Lucide 图标。标题栏提供“正文显示”快速开关，与设置页共享同一状态；切换时只刷新正文展示层并原地同步复选框，不重新读取或重建侧栏列表。侧栏会记录当前展示的笔记路径，工作区焦点在侧栏和同一篇正文之间切换时不重建列表，只有笔记路径变化或明确要求强制刷新时才重新读取。侧栏读取批注时会针对当前正文重新解析锚点，按照实际起止偏移从上到下排列，并显示解析后的实时行列。每条批注是独立列表项，包含锚点摘要、编辑框、保存状态、重定位、跳转和删除操作；重定位会用批注所属编辑器的当前选区或光标创建新锚点，保留批注 ID、内容和创建时间，并要求编辑器装饰放弃旧实时位置、重新解析新锚点。所有正文和批注内容都以文本节点或表单值写入，不拼接 HTML。

## 正文展示

正文展示开关保存在插件设置中，不进入批注 JSON，因此打开或关闭不会触发数据迁移。

编辑模式：

- 选区或位置锚点继续使用原有高亮/标记。
- 有内容的批注在锚点结束行与下一行之间插入 CodeMirror `block` widget；末行批注放在文档末尾。
- widget 只读，点击后调用统一的 `openAnnotationInSidebar(sourcePath, annotationId)`。
- widget 不存在于 `EditorState.doc`，所以不会参与 Markdown 保存，也不会改变锚点偏移。

阅读模式：

- 通过 `registerMarkdownPostProcessor` 获取渲染区段的 `lineStart`/`lineEnd`。
- 使用同一条 `annotationDisplayLine` 规则筛选当前区段的批注。
- 将只读按钮插入当前 Markdown 渲染块之后，并通过 `MarkdownRenderChild` 管理生命周期。
- 阅读模式没有可靠的字符级 DOM 映射，因此展示粒度是“锚点结束行所属区段”，而不是重新包裹渲染后的单个字符。

两种模式都以纯文本渲染批注正文，保留换行但不执行批注中的 Markdown 或 HTML，避免批注内容改变正文结构或引入额外交互。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `src/core.ts` | 路径、格式校验、锚点创建与解析 |
| `src/repository.ts` | Vault 伴随文件 CRUD 与生命周期同步 |
| `src/annotation-view.ts` | 原生侧栏渲染与编辑交互 |
| `src/editor-highlights.ts` | CodeMirror 文本高亮和位置标记 |
| `src/inline-display.ts` | 正文展示行归属、排序和空内容规则 |
| `src/reading-annotations.ts` | 阅读模式 Markdown 后处理和点击跳转 |
| `src/settings.ts` | 插件设置 |
| `src/main.ts` | 插件注册、命令、事件与模块编排 |

## 构建产物

源码与发布文件分离：根目录的 `manifest.json` 和 `styles.css` 是构建输入，esbuild 将代码打包到 `dist/main.js`，并把这两个静态文件复制到 `dist/`。构建开始时会清理旧 `dist/`，避免已删除或重命名的文件残留在发布目录中。
