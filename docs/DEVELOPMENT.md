# 开发说明

## 类型与颜色验收

在选中文本批注和单点批注上分别切换配置的类型，确认侧栏卡片、编辑模式高亮/标记/正文批注块和阅读模式批注块同步变化；在设置中新增、重命名、修改颜色并删除类型，确认展示和已有批注行为正确。

## 环境

- Node.js 22 或更高版本（vitest 5 要求 `^22.12` / `^24` / `>=26`）。
- npm 10 或更高版本。
- Obsidian 1.4.0 或更高版本。

## 常用命令

```powershell
npm install
npm run dev
npm test
npm run build
npm run check
```

`npm run dev` 会监听 TypeScript 变化并重建 `dist/main.js`。`npm run build` 会先清理 `dist/`，再生成 `main.js` 并复制 `manifest.json`、`styles.css`，因此 `dist/` 始终是一份完整的可安装插件。`dist/` 已加入 `.gitignore`，构建产物不提交到 Git。`npm run check` 依次运行全部测试、TypeScript 检查和生产构建。

## 本地调试

1. 执行 `npm run build`。
2. 将 `dist/` 目录复制或链接到 `<Vault>/.obsidian/plugins/annotation-sidebar/`。
3. 确认插件目录中有 `manifest.json`、`main.js` 和 `styles.css`。
4. 在 Obsidian 中启用插件。源码修改后执行构建，再使用“重新加载应用”或第三方插件热重载工具。

## 手工验收清单

- [ ] 选中文本添加批注，侧栏自动打开并聚焦输入框。
- [ ] 无选区时在光标位置添加批注。
- [ ] 停止输入后状态从“等待保存”变为“已保存”。
- [ ] 关闭并重新打开 Obsidian 后批注仍存在。
- [ ] 点击行号和定位图标能回到正文锚点。
- [ ] 点击侧栏中的行号或定位图标时，正文正确跳转且侧栏列表不闪烁、不重置滚动位置。
- [ ] 在正文中选择文本后点击批注的重定位按钮，批注绑定到该选区并按新位置重新排序。
- [ ] 正文没有选区时点击重定位按钮，批注绑定到当前光标位置。
- [ ] 批注所属笔记未在编辑器中打开时，重定位被拒绝且原锚点不变。
- [ ] 批注文件中的数组顺序被打乱时，侧栏仍按照正文锚点从上到下排列。
- [ ] 在批注锚点前插入正文并刷新侧栏后，排序和显示行号反映当前正文位置。
- [ ] 在锚点前插入文字后仍能正确跳转。
- [ ] 重复原文存在时能依据上下文跳到正确一处。
- [ ] 删除最后一条批注后伴随文件消失。
- [ ] 重命名笔记后伴随文件同步重命名，JSON 中 `source` 更新。
- [ ] 删除笔记后伴随文件进入配置的废纸篓。
- [ ] 手工破坏 JSON 后侧栏报错且原文件不被覆盖。
- [ ] 浅色和深色主题中侧栏、选区高亮、光标标记均清晰。
- [ ] 开启“在正文中显示批注”后，编辑模式会在锚点结束行下方显示批注块。
- [ ] 开启“在正文中显示批注”后，阅读模式会在对应渲染区段下方显示批注块。
- [ ] 关闭正文展示开关后，两种模式中的批注块都消失，侧栏数据仍保留。
- [ ] 在侧栏标题栏切换“正文显示”后，设置页和正文展示状态保持一致。
- [ ] 在侧栏或设置页切换“正文显示”时，侧栏列表、滚动位置和输入框状态不闪烁或重置。
- [ ] 点击编辑模式正文批注块或位置标记，侧栏打开并聚焦对应批注输入框。
- [ ] 点击阅读模式正文批注块，侧栏打开并聚焦对应批注输入框。
- [ ] 在正文批注上方按回车时，批注保持在锚点行下方且不发生二次跳动。
- [ ] 在正文批注下方行首按退格删除换行时，批注立即重定位且不会短暂消失。
- [ ] 末行、位置锚点和同一行多个批注在连续编辑时保持稳定。
- [ ] 选区跨越多个段落、位于列表、引用、Callout、表格和代码块时，批注只出现一次且位于结束行所属区段之后。
- [ ] 批注正文包含换行、Markdown 符号或 HTML 字符时按纯文本显示。

## 发布

1. 更新 `package.json`、`manifest.json` 和 `versions.json` 中的版本。
2. 更新 `CHANGELOG.md`。
3. 执行 `npm ci` 和 `npm run check`。
4. 合并改动并推送到 `master`。
5. 打与版本号同名的标签并推送，例如 `git tag 0.4.0 && git push origin master --follow-tags`。

标签推送后，`.github/workflows/release.yml` 会校验三处版本与标签一致、运行测试、构建，然后把 `dist/` 中的 `main.js`、`manifest.json`、`styles.css` 发布为 GitHub Release，发布说明取 `CHANGELOG.md` 中对应版本的条目。版本不一致或 `versions.json` 缺少该版本时流水线会直接失败。
